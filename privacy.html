Privacy Policy — SMS Automations

Effective Date: October 7, 2026
Application: SMS Automations
Package: com.smsforwarder
Version: 1.0.0 (versionCode 6)
Summary of Core Principle: SMS Automations processes all incoming SMS and text MMS entirely on your local physical device. The application does not connect to any servers, does not request the Android Internet permission, contains zero analytics or telemetry SDKs, and stores no message bodies on disk.

1. Core Commitment: 100% Local-First Architecture

SMS Automations is engineered from the ground up to respect user privacy and adhere to the principle of least privilege. The application operates exclusively on your device:

  • No Remote Servers: The application does not maintain, connect to, or interact with any cloud backend, server infrastructure, or remote API endpoint.
  • No Internet Access: The application does not declare or request the android.permission.INTERNET permission in its Android Manifest. Under the Android OS security model, the operating system prevents the application from opening network sockets or transmitting data to remote internet servers.
  • No Analytics / No Trackers: The application includes no third-party software development kits (SDKs), no advertising networks, no crash reporting beacons, and no behavioral analytics or telemetry frameworks.
  • No Account Required: The application requires no user account, registration, login credentials, email address, or third-party authentication.
  • Carrier Cellular Transmission (Not End-to-End Encrypted): Forwarded messages leave your device via your mobile carrier's cellular radio stack to reach your designated destination phone numbers according to your configured rules. SMS Automations operates strictly locally on your device and does not run intermediary servers, cloud relays, or developer collection endpoints. However, users should note that standard cellular SMS and text MMS transmissions are handled by telecommunications carriers and are not end-to-end encrypted. Message contents transmitted over cellular networks are subject to carrier-level telecommunications routing.

2. Permissions & How They Are Used

SMS Automations requests only the minimum set of permissions necessary to deliver its core on-device message routing capabilities:

Permission Technical Name Purpose & Scope
Receive SMS RECEIVE_SMS Used solely to detect incoming cellular SMS messages in real time and evaluate them against your locally configured automation rules.
Receive MMS RECEIVE_MMS Used solely to receive incoming cellular MMS notifications (WAP Push) in real time to detect messages from configured senders.
Read SMS READ_SMS Used strictly under least-privilege to query the text content of downloaded MMS messages from the system telephony provider (content://mms). The app never scans your historical inbox, never imports messages, and never stores text on disk.
Send SMS SEND_SMS Used solely to transmit forwarded SMS messages to your designated destination phone numbers via your carrier's cellular radio stack.
Run at Startup RECEIVE_BOOT_COMPLETED Used solely to ensure your locally configured automation rules remain active after your device restarts.

Explicitly Excluded Permissions: To ensure device integrity and user privacy, the application does NOT request or use any of the following sensitive permissions:

  • × android.permission.INTERNET
  • × android.permission.WRITE_SMS
  • × android.permission.READ_CONTACTS
  • × android.permission.WRITE_CONTACTS
  • × android.permission.ACCESS_FINE_LOCATION
  • × android.permission.ACCESS_COARSE_LOCATION
  • × android.permission.READ_PHONE_STATE
  • × android.permission.READ_CALL_LOG
  • × android.permission.WRITE_CALL_LOG
  • × android.permission.POST_NOTIFICATIONS

3. Data Storage & Privacy Protections

A. Message Bodies and OTP Codes

The application never stores message bodies (SMS or MMS text) on disk or in persistent storage.

One-time passcodes (OTPs), authentication codes, banking notifications, and personal text communications are processed transiently in volatile device memory and discarded immediately upon forwarding or rule evaluation. Media attachments in MMS messages (photos, videos, audio) are never stored, saved, or processed.

B. Local Automation Rules

Your configured automation rules (sender conditions, optional keyword filters, destination phone numbers, and SIM slot selections) are stored locally in app-private storage (SharedPreferences).

Android cloud backup is explicitly disabled (android:allowBackup="false") in the application manifest to prevent unintentional automated uploads of your rules to Google Drive or third-party backup clouds.

C. Local Activity History & Diagnostics

  • The application maintains an in-device activity log strictly bounded to a maximum ring buffer of 100 events.
  • Stored records contain only: event type (FORWARD_SUBMITTED, SENT, DELIVERED, SEND_FAILED, NO_RULE_MATCHED, DUPLICATE_SUPPRESSED, LOOP_BLOCKED), event timestamp, destination recipient count, failure category (if any), and a redacted/masked sender phone number (e.g., +336****44).
  • Diagnostic logcat logs and user-initiated diagnostic report exports contain zero raw unmasked phone numbers and zero SMS message bodies.

4. User Control & Data Deletion Rights

You retain total control over all configuration data on your device at all times:

  • Clear Activity History: You can purge all stored activity records at any time directly from the application's Settings screen by tapping Clear history.
  • Delete Automations: You can edit, deactivate, or permanently delete individual automation rules at any time.
  • Local Rule Backups: Rule backups exported via the Android Storage Access Framework are stored as plain JSON on your selected local directory. You may inspect or delete these backup files using any file manager.
  • App Uninstall: Uninstalling the application completely deletes all configuration files, activity records, and internal caches stored in app-private storage by the Android OS runtime.
